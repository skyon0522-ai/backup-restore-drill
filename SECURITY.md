# Synthetic recovery boundary

The drill creates its own five-file fixture and uses a fixed public demo
password. It is not an interface for backing up private business data. The
copied Rustic engine retains its upstream capabilities and licenses; the
verified exercise uses only a local repository.

The runner requires a new work directory and keeps its build cache outside the
checkout and work directory. It never deletes prior output or caches. New
work/review directories use private Linux permissions; review files use mode
600. A failed or interrupted operation can retain partial new output.
Interrupted-write and power-loss recovery were not verified.

The reader hashes current generated source/restored files and compares literal
bytes. It rejects static symlinks/special files, traversing manifest entries,
inconsistent saved gates and existing/overlapping output. Files changing during
inspection are outside its verified scope. Editable records are not
authenticated; hashes are not signatures or proof of origin.

Review files retain names, sizes, digests, snapshot IDs and selected saved
check fields. They do not copy file contents, passwords, backup keys or the
machine-specific CLI path. Inspect metadata before sharing. Original data and
logs stay in the separate workspace; do not publish private data there.

Report a bug with a synthetic reproducer in the
[issues](https://github.com/skyon0522-ai/backup-restore-drill/issues).
For sensitive vulnerabilities, use **Report a vulnerability** on the
[security page](https://github.com/skyon0522-ai/backup-restore-drill/security)
if available; otherwise request a private channel without posting exploit
details or sensitive data. This does not assert that private reporting is enabled.
